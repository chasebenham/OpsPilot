# Synthetic AI evaluation

The preserved original dataset is `evaluation/cases.json` (`meridian-synthetic-30-v1`). `evaluation/cases-v2.json` (`meridian-synthetic-100-v2`) includes the original cases and 70 template-derived examples. It fixes an original label that treated a monthly subscription price as a total commitment. Templates make cases correlated and do not replace a diverse independent benchmark. All 100 labels await human review; `evaluation/review-report-v2.json` lists them. A versioned rubric is in [evaluation-rubric.md](evaluation-rubric.md). Regenerate and validate with `python -m evaluation.expand_dataset` and `python -m evaluation.validate_dataset` from `backend`. Automated checks are not expert review.

Operations Admins can explicitly start a billable evaluation. The API checks the estimate against the supplied budget, records the model, prompt hash, dataset hash, timeout and prices, and persists each attempted synthetic case. A database uniqueness index prevents concurrent runs. The service stops after three consecutive errors. An interrupted run can be marked Interrupted using the admin endpoint after twice its configured worst-case timeout plus five minutes; in-flight workers recheck status under a lock. Results already stored remain available. Runs are synchronous: HTTP timeouts or server restarts can interrupt the response, and there is no resume mechanism.

Balanced selection interleaves the three categories and prioritizes cases flagged for review; dataset-order selection is also available. The chosen case IDs and selection method are stored with the run. Small selections cannot cover every edge case and the labels still require human adjudication. No evaluation runs automatically.

The preflight price is an estimate, not a provider-enforced budget or an invoice. The application uses configured `OPENAI_TIMEOUT_SECONDS` and zero provider retries. Estimated costs are unavailable if any attempt failed or usage is missing. Verify current provider prices separately.

Classification, priority and department accuracy use attempted cases as denominator, including failed calls; classification among successful calls is also reported. Review recall includes failed mandatory-review cases. Extraction match and missing-keyword recall include expected fields from failed cases in their denominators. Keyword matching is not semantic evaluation, and missing-information precision cannot be estimated without negative labels. The confusion matrix contains valid responses only; category recall includes failures. F1 excludes categories with no expected cases. Review metrics include deterministic safety overrides. The pilot had only three IT cases and must not be generalized to all categories. Do not describe mocked results as live performance.

On 2026-11-21 (America/Phoenix), a three-case live pilot using `gpt-6-luna` completed all three calls with schema-valid results and no recorded provider errors. The three IT classifications matched the pending labels, two of three priorities matched, and one of three expected missing-information keywords matched. One team-wide CRM case was labeled Critical but the model suggested High; the label requires adjudication. The provider reported 2,468 input and 1,810 output tokens. At the supplied illustrative standard rates of $0.10 and $0.50 per million input and output tokens, the calculated cost is $0.001152; this is not billing data. The small, single-category sample is not a model-performance estimate.
